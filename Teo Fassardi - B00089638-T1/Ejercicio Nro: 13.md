# Ejercicio Nro. 13

## Enunciado

1. ¿Qué es Extreme Programming (XP) y cuál es su objetivo principal dentro de las metodologías ágiles?

2. ¿Cuáles son los cinco valores principales de XP? Explicá brevemente cada uno.

3. ¿Por qué XP considera que las pruebas son un elemento fundamental del desarrollo de software?

4. ¿Qué es Test Driven Development (TDD) y cómo se relaciona con XP?

5. ¿En qué consiste la práctica de Pair Programming? Mencioná dos ventajas y una posible dificultad.

6. ¿Qué son las historias de usuario en XP y por qué se prefieren frente a una especificación extensa de requisitos?

7. ¿Qué significa Continuous Integration en XP y qué beneficios aporta al equipo de desarrollo?

8. ¿Cómo se aplica el concepto de Weekly Cycle en un proyecto desarrollado con XP?

9. En XP se plantea que se fija el tiempo, el costo y la calidad, y se negocia el alcance. ¿Qué significa esta idea? Explicalo con un ejemplo.

10. Elegí tres prácticas de XP y explicá cómo podrían aplicarse en un proyecto real de desarrollo de software.

## Resolución

1. Extreme Programming, o XP, es una metodología ágil de desarrollo de software que busca entregar software de calidad mediante ciclos cortos,
   comunicación constante, pruebas frecuentes y adaptación al cambio. Su objetivo principal es responder rápidamente a las necesidades del cliente,
   reduciendo errores y mejorando continuamente el producto.
   
2. Los cinco valores principales de XP son: comunicación, simplicidad, retroalimentación, valentia y respeto. La comunicación permite que el equipo y
   el cliente estén alineados. La simplicidad busca hacer solo lo necesario, evitando soluciones complicadas. La retroalimentación permite corregir errores
   rápidamente. La valentia ayuda a cambiar lo que no funciona y mejorar el diseño. El respeto implica valorar el trabajo y las opiniones de todos
   los miembros del equipo.

3. XP considera que las pruebas son fundamentales porque permiten detectar errores de forma temprana y asegurar que el software funcione correctamente.
   Además, ayudan a que los cambios puedan hacerse con más seguridad, ya que si algo se rompe, las pruebas permiten identificarlo rápido.

4. Test Driven Development, o TDD, es una práctica en la que primero se escriben las pruebas y después se desarrolla el código necesario para
   que esas pruebas se cumplan. Se relaciona con XP porque ayuda a construir calidad desde el inicio, evita errores y obliga a pensar claramente
   qué debe hacer cada funcionalidad antes de programarla.

5. Pair Programming consiste en que dos programadores trabajen juntos en una misma tarea. Uno escribe el código y el otro revisa, piensa alternativas
   y detecta posibles errores. Dos ventajas son que mejora la calidad del código y permite compartir conocimientos entre los integrantes del equipo.
   Una posible dificultad es que puede generar conflictos si los dos programadores no se comunican bien o tienen formas muy distintas de trabajar.

6. Las historias de usuario son descripciones simples de una necesidad del usuario, escritas desde su punto de vista.
   Por ejemplo: “Como usuario, quiero iniciar sesión para acceder a mi cuenta”. Se prefieren frente a especificaciones extensas porque son más claras,
   fáciles de entender y permiten enfocarse en el valor que necesita el cliente.

7. Continuous Integration significa integración continua. Consiste en integrar frecuentemente el código desarrollado por los distintos miembros del equipo,
   para detectar problemas lo antes posible. Sus beneficios son reducir errores, evitar conflictos grandes entre partes del sistema y mantener siempre una
   versión funcional del software.

8. El Weekly Cycle se aplica organizando el trabajo en ciclos semanales. Al inicio de la semana se planifican las tareas más importantes, durante la semana
   se desarrollan y al final se revisa el avance. Esto permite mantener un ritmo constante, detectar problemas rápidamente y ajustar el plan según las necesidades
   del proyecto.

9. Esta idea significa que en XP se intenta mantener fijos el tiempo de entrega, el costo del proyecto y la calidad del software, pero se puede
   modificar el alcance si es necesario. Por ejemplo, si una aplicación debe entregarse en cuatro semanas y el equipo no llega con todas las funciones,
   se priorizan las más importantes y se dejan algunas secundarias para una próxima versión, sin bajar la calidad ni atrasar la entrega.

10. Tres prácticas de XP que podrían aplicarse en un proyecto real son Pair Programming, TDD y Continuous Integration. Pair Programming podría usarse para
    desarrollar funcionalidades complejas entre dos programadores y reducir errores. TDD podría aplicarse escribiendo pruebas antes de programar cada función
    importante, asegurando que cumpla con lo esperado. Continuous Integration podría utilizarse integrando el código todos los días en un repositorio compartido,
    para detectar conflictos y errores rápidamente.
